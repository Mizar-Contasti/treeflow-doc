# Webhook

La pestaña **Webhook** no tiene buscador ni botón de crear. Hay una sola tarjeta, **Webhook**. No se borra y no se duplica. No aparece en **Añadir herramienta…**: el nodo la pide aparte.

![La pestaña Webhook, con una sola tarjeta](/img/herramientas/webhook-lista.png)

## El editor

Se abre igual que una API. El **nombre** está fijo en Webhook. La descripción de fábrica es «Webhook principal del sistema». El método es **POST** y el timeout de fábrica es **30000** ms. La autenticación puede quedar en ninguna, o pasar a Basic o Bearer.

![Webhook: POST, 30000 ms, cuerpo vacío y el aviso de {$variable}](/img/herramientas/webhook-editor.png)

La **URL** tiene que empezar por `http://` o `https://`. Vacía, o con el interruptor apagado, el motor no llama a nada. El interruptor está en la cabecera del editor, junto a **Guardar cambios**.

El cuerpo es un JSON. El aviso de esa caja dice cómo meter datos:

```
{$variable}
{ $valor ? 'Sí' : 'No' }
```

**Entrada** y **Salida** funcionan como en una [API](./Apis): lo que el cuerpo va a leer, y lo que quieres guardar de la respuesta. **Pruebas** hace la llamada. **Despliegue** la marca. Para que el nodo la use bastan el interruptor encendido y una URL http(s): el estado de la pantalla no sustituye a eso.

**Mensaje si falla** es lo que ve la persona si esa URL no contesta y no hay valor de respaldo.

## Cuándo corre

En el nodo, pestaña **Funcionalidad**, **Llamar webhook en este nodo**. Si está encendido, el motor llama a esta URL al pasar por ahí, después de los scripts y antes que las APIs de ese nodo. Si el árbol no tiene webhook activo, el interruptor no hace nada.

Lo llevan el contexto, la intención y el evento. Si el nodo de origen y el de destino lo piden los dos, se llama una vez y cuenta el de destino.

No es el webhook de un canal. Ese lo configura la plataforma (Meta, Slack, Discord) para entregarle mensajes a TreeFlow, y vive en [Canales](/docs/Canales/CanalesDeComunicacion).
