# Entidades

En el menú se llaman **Entidades**. Son los datos que el motor saca de una frase: un producto, una fecha, un número. La [intención](./Intenciones) decide qué quiso decir la persona. La entidad decide qué trozo de la frase se guarda.

## La lista

**Entidades** abre las tarjetas. Arriba se busca por nombre. Hay cuatro pestañas.

![Lista de entidades simples, con buscador y Nueva Entidad](/img/entidades/lista.png)

| Pestaña | Qué guarda |
|---|---|
| **Simple** | Un valor y las formas de decirlo |
| **Compuesta** | Varias entidades juntas en una sola frase |
| **Regex** | Un formato fijo, con una expresión regular |
| **Sistema** | Las que ya trae Treeflow (`sys.number`, `sys.date`…) |

- **Nueva Entidad** abre el formulario. Si estás en Compuesta o Regex, el tipo ya viene elegido.
- Un clic en el nombre abre el editor.
- La franja naranja pide confirmación para borrarla. Si una intención la está usando, el borrado avisa.
- **Sistema** no se borra ni se edita.

## El formulario

Arriba, **Nombre de entidad** y **Tipo**. **Guardar cambios** escribe la entidad. **Limpiar todo** vacía los valores y pide confirmación.

El nombre es un identificador. Los espacios pasan a `_`. Al guardar queda en minúsculas y sin acentos. La `ñ` se conserva.

Si el árbol tiene más de un idioma, junto al nombre están los idiomas: cada uno edita sus sinónimos.

Abajo está el **Probador de entidad**. Sirve para ver si una frase cae en un valor, sin entrenar el árbol.

## Simple

Una simple es una lista de valores. Cada valor tiene una **clave** —lo que se guarda— y **sinónimos** —otras formas de decirlo—.

![producto: pizza, hamburguesa, taco, refresco y ensalada, cada uno con sus sinónimos](/img/entidades/simple.png)

- La clave se escribe abajo y se confirma con **Enter**. Varias claves separadas por coma entran de una vez: `pizza, hamburguesa`.
- En **Añadir sinónimo** pasa lo mismo: Enter, o varios separados por coma.
- La clave también cuenta como forma de decirlo. `pizza` entra aunque no esté repetida en los sinónimos.
- Un clic en la clave o en un sinónimo lo edita. La X del sinónimo lo quita. La basura quita el valor entero.

`quiero una pizza` y `quiero una pizzas` caen en la clave `pizza`, porque `pizzas` es sinónimo.

Si en una simple escribes `@` para citar otra entidad, el formulario pregunta si la conviertes a **Compuesta**.

## Compuestas {#2-entidades-compuestas}

Una compuesta lee **varias entidades a la vez**. `2 pizzas` es un número y un producto, y es un solo renglón.

Cada fila es una forma válida de decirlo. Se escribe el patrón y se confirma con Enter.

![Una fila compuesta: cantidad con sys.number y producto](/img/entidades/compuesta.png)

```
@sys.number:cantidad @producto:producto
@sys.number:cantidad @producto:producto de @sabor
@producto:producto
```

- `@producto` cita la entidad `producto`.
- `@producto:producto_pedido` cita esa entidad y guarda el dato con el nombre `producto_pedido`. Sin los dos puntos, el parámetro se llama igual que la entidad.
- Las palabras entre medias, como `de`, tienen que estar en la frase.
- El motor se queda con la fila que rellene más huecos.
- Una frase puede traer varios renglones. `1 pizza y 2 tacos` son dos. El detalle está en [un parámetro con varios valores](/docs/Avanzado/Parametros#un-parámetro-con-varios-valores).

En la fila, cada `@` se pinta. La basura quita esa fila.

## Regex {#3-entidades-regex}

Una regex reconoce un formato, no una lista de palabras. Sirve para una CURP, una ficha, un código.

![ficha: el patrón regex, marcado como válido, y la opción de añadir otra variante](/img/entidades/regex.png)

El campo **Patrón regex** avisa si la expresión es válida. **Añadir variante** suma otro patrón: basta con que uno coincida. Enter en el campo abre la variante siguiente.

En `ficha` el patrón es el de una CURP: cuatro letras, seis números, `H` o `M`, y el resto del formato.

En el probador de una regex, lo que escribes se pasa a mayúsculas y se le quitan los espacios, para probar el formato limpio.

## Probador

El probador está en el mismo formulario. Escribes una frase y dice si cayó en un valor.

![quiero una pizza cae en la clave pizza, coincidencia exacta](/img/entidades/probador.png)

- **Valor capturado** es la clave que se guarda.
- **Tipo** dice si fue exacta, normalizada (sin acentos, parecida) o por el patrón.
- Si no hay valores todavía, el campo pide que los agregues primero.
- Las de **Sistema** no se prueban aquí: las detecta el motor.

El probador no sustituye el entrenamiento. Para ver la frase dentro de una conversación, se guarda, se entrena y se prueba en la [consola](/docs/Avanzado/Consola).

## Sistema

La pestaña **Sistema** lista las que ya vienen. No se editan. En una [intención](./Intenciones) se citan como `@sys.number`, `@sys.date`, `@sys.time`.

![Las entidades del sistema: número, fecha, correo, teléfono y el resto](/img/entidades/sistema.png)

| Nombre | Qué reconoce |
|---|---|
| `sys.number` | Números, también escritos con letra |
| `sys.date` | Fechas: mañana, 10 de mayo, martes |
| `sys.time` | Horas: 10, 10:30, 3pm |
| `sys.email` | Correos |
| `sys.phone` | Teléfonos |
| `sys.currency` | Montos: $25.50, 100 pesos |
| `sys.any` | Cualquier texto corto |

El icono de cada tarjeta abre el detalle: ejemplos y el formato en que sale el valor. La lista completa, con el resto (`sys.url`, `sys.zipcode`, `sys.quantity`…), está en [entidades del sistema](/docs/Misc/HojasDelSistema).

## Entrenar

**Guardar cambios** deja el árbol desactualizado. Los valores nuevos entran en la conversación cuando se entrena, con el botón **Entrenar** de abajo en el menú.

Una entidad que ninguna intención cita no se pregunta sola. Hay que marcarla en un [patrón](./Intenciones) o usarla como parámetro requerido.
