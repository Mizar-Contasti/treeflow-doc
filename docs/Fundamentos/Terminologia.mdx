# Terminología

Cada nombre del menú es una cosa distinta. Esta página es el mapa: qué es cada una y cómo se encadenan.

![El panel, con el menú de la app: flujos, intenciones, entidades y canales](/img/intro/panel.png)

## El mapa

| En el menú | Qué es |
|---|---|
| **Árbol** | El bot. También se crea como «un bot nuevo». Guarda el entrenamiento, los flujos y todo lo demás. |
| **Flujo** | El dibujo del lienzo: nodos y flechas. Ordena el recorrido. |
| **Nodo** | Un paso de ese lienzo: un mensaje, una intención, una validación u otro. |
| **Intención** | Lo que el motor reconoce en una frase: patrones, parámetros y la respuesta. |
| **Entidad** | Un tipo de dato que se saca de la frase: un sabor, una fecha, un número. Simple, compuesta o regex. |
| **Parámetro** | El hueco con nombre donde cae ese dato (`@sabor:sabor` → el parámetro `sabor`). |
| **Mensaje** | Una respuesta reutilizable: texto, botones, carrusel, HTML. |
| **Captura** | Cómo se pide un dato que falta, y qué se dice si no se entiende. |
| **Canal** | Por dónde habla la persona: el widget web, Telegram, WhatsApp y el resto. |
| **Herramienta** | Lo que el bot llama afuera: un script, una API, el webhook, una transferencia. |
| **Consola** | El panel de la derecha. Ahí se prueba el bot y, si quieres, lo diseña la IA. |

## Cómo se encadenan

Un pedido en un restaurante, con los nombres de la app:

1. La persona escribe en un **canal** (el widget de la página, por ejemplo).
2. El **árbol** recibe la frase. Una **intención** (`pedir`) la reconoce porque se parece a sus patrones.
3. En el patrón, `@sabor` apunta a una **entidad**. De «de queso» sale el **parámetro** `sabor`.
4. Si falta el tamaño, una **captura** pregunta «¿de qué tamaño?» y, si la respuesta no sirve, insiste.
5. El **flujo** decide el nodo siguiente. Ese nodo muestra un **mensaje** («Listo, una grande de queso») o llama una **herramienta** (el inventario, la caja).
6. La respuesta vuelve por el mismo canal.

Si en ese momento hace falta una persona, la [mesa de ayuda](/docs/Avanzado/MesaDeAyuda) toma la conversación y se la puede devolver al bot.

## Cuándo usar cada cosa

**Canales**, cuando la persona tiene que hablar con el bot por otro lado: la web, WhatsApp, Telegram.

**Herramientas**, cuando el bot tiene que leer o escribir en otro sistema: stock, un CRM, un correo, una validación.

**Workspace**, cuando hay otro cliente, otro equipo o otro entorno. Cada uno tiene sus árboles, sus canales y sus claves. Dentro de un workspace, un árbol nuevo no pide otro workspace.

El detalle largo de cada uno sigue en su página: [workspaces](/docs/Avanzado/Workspaces), [canales](/docs/Canales/CanalesDeComunicacion) y [herramientas](/docs/Herramientas).

## Diseñar, no rellenar formularios

El diseño es decidir el recorrido, las preguntas y las respuestas. La IA puede hacer el trabajo de la app, porque tiene herramientas para crear y modificar flujos, intenciones, entidades y mensajes, y para entrenar y probar.

- En la [consola](/docs/Fundamentos/ProbarElBot), pestaña Agente, se lo cuentas ahí mismo.
- Desde fuera, una clave [MCP](/docs/Avanzado/Credenciales) deja que otro asistente (por ejemplo Claude Desktop) entre al workspace y opere las mismas piezas.

## Los nombres de antes

Si una página vieja no coincide con el menú, esta es la traducción.

| Antes | Ahora |
|---|---|
| Rama | Intención. El lienzo se llama flujo. |
| Hoja del lienzo | Nodo |
| Hoja, cuando se hablaba de extraer datos | Entidad |
| Editor visual, Canvas Engine | Flujos |
| Injerto | Canal |
| Fertilizante | Herramienta. El webhook global es la pestaña Webhook. |
| QWidget | El widget web, en Canales |
| Reforestación, pipeline de seis fases | El agente de la consola, o un asistente por MCP |
