# Cómo funciona por dentro

Para quien integra, depura o quiere saber qué pasa entre que escribes un encargo y que el bot cambia.

El agente vive **dentro del backend principal** (`backend/core/builder_agent/`). No hay un servicio aparte: el servicio generativo independiente del puerto 8001 se retiró. Se usa a través de la API `/api/builder-agent`.

## Lo que pasa con cada mensaje

1. **La consola envía** el bot, el historial de la conversación y, si lo eligió el usuario, la credencial y el modelo.
2. **El servidor comprueba** que el bot sea del workspace de quien pregunta.
3. **Elige la credencial**: la indicada (debe ser del workspace) o, si no se indica, la primera credencial de IA del workspace. Sin ninguna, responde que hace falta una clave.
4. **Arma las instrucciones** del modelo en el **idioma principal del bot**: el identificador, el nombre y el propósito del bot, la lista de sus flujos, las reglas de nombres, dónde aplicar los cambios y el protocolo de **mirar antes de crear**.
5. **Recorta el historial** a los **últimos 14 mensajes**.
6. **Llama al modelo** con las instrucciones, el historial y las **46 herramientas**, descritas en el idioma del bot. Cada llamada espera hasta 60 segundos.
7. **Si el modelo pide herramientas**, el servidor las ejecuta y le devuelve el resultado. Repite hasta **8 rondas**.
8. **Si el modelo responde sin pedir más**, ese texto es la respuesta. Se guarda la conversación con las acciones ejecutadas y vuelve a la consola.

Si llega a las 8 rondas sin respuesta final, devuelve *Límite de iteraciones alcanzado sin respuesta final*, con las acciones que sí llegó a ejecutar.

## Cómo se ejecuta una herramienta

El servidor llama a la herramienta con los argumentos que dio el modelo **más el contexto de la sesión**: el bot, el workspace y el usuario. El contexto de la sesión **gana** a lo que el modelo haya escrito. Un modelo que se equivoque —o que reciba una instrucción maliciosa dentro de un texto— no puede salirse del bot ni del workspace.

Si una herramienta falla, el error vuelve al modelo como resultado para que lo explique o lo intente de otra forma.

## Cómo habla con los proveedores

Con **Anthropic** usa su API nativa (`/messages`): las instrucciones van aparte, las herramientas se describen con su esquema de entrada, y el resultado de cada herramienta vuelve como un bloque `tool_result`. Con **todos los demás proveedores** usa el **formato de chat de OpenAI** (`/chat/completions`, con las herramientas como funciones): Gemini y los demás exponen una ruta compatible; con Ollama o un servidor propio, tú pones la URL base. El ciclo es el mismo en ambos casos; sólo cambia cómo se traduce la petición y la respuesta. Ver [Proveedores y modelos](/docs/Agente/ModelosGenerativos).

## Endpoints

Todos exigen sesión iniciada y trabajan sobre un bot del workspace.

| Método y ruta | Para qué |
|---|---|
| `POST /api/builder-agent/chat` | Un turno del agente: devuelve el texto, las acciones y el `session_id` |
| `POST /api/builder-agent/confirm` | Ejecuta una herramienta ya decidida, tras el visto bueno del usuario |
| `GET /api/builder-agent/sessions` | Las conversaciones guardadas de un bot, la más reciente primero |
| `GET /api/builder-agent/sessions/{id}` | Una conversación entera |
| `PUT /api/builder-agent/sessions/{id}/messages` | Reemplaza los mensajes guardados de una conversación |
| `DELETE /api/builder-agent/sessions/{id}` | Borra una conversación |

Si no hay credencial, `chat` responde `400` con `key_required: true`; la consola abre entonces la configuración.

`chat` llama a un modelo de pago, así que tiene un límite de **20 mensajes por minuto por usuario**: pasado ese límite responde `429` con un aviso, sin llamar al proveedor.

## Lo que se guarda

Cada conversación queda en la tabla de sesiones del agente, con su bot, su workspace, el usuario, un **título** (los primeros 60 caracteres del primer mensaje), los mensajes y las acciones. Se listan por bot, y por eso el historial es por bot.

Las **credenciales de IA** se guardan en la misma tabla de credenciales del workspace que las de los canales, con el tipo del proveedor y su configuración: la clave, la URL base y el modelo.
