# 🧪 Fertilizantes

Los **Fertilizantes** en TreeFlow son webhooks especializados que se ejecutan cuando tu árbol conversacional procesa mensajes, permitiendo integrar sistemas externos y enriquecer las conversaciones con datos y funcionalidades adicionales.

## ¿Qué son los Fertilizantes?

Los Fertilizantes son el mecanismo de TreeFlow para conectar tu chatbot con el mundo exterior. Funcionan como "nutrientes" que enriquecen las conversaciones con:

- **Datos externos**: Información de CRM, bases de datos, APIs
- **Validaciones**: Verificación de datos en tiempo real
- **Acciones**: Envío de notificaciones, creación de tickets, etc.
- **Integraciones**: Conexión con servicios empresariales

### Diferencia con Injertos

Es importante entender la diferencia:

| Concepto | Propósito | Ejemplo |
|----------|-----------|---------|
| **Injertos** | Canales de comunicación | Widget Web, WhatsApp, Telegram |
| **Fertilizantes** | Integraciones con APIs | CRM, validadores, notificaciones |

**Analogía**: Los Injertos son las "bocas y oídos" del bot (cómo habla con usuarios), los Fertilizantes son el "cerebro externo" (cómo obtiene información y ejecuta acciones).

## Tipos de Fertilizantes

TreeFlow ofrece dos tipos de Fertilizantes con propósitos diferentes:

### 🌟 Fertilizante Principal

El **Fertilizante Principal** es el webhook global que procesa **todas** las interacciones del workspace.

#### Características:
- **Único por workspace**: Solo uno puede estar activo
- **Procesamiento global**: Se ejecuta en cada respuesta del bot
- **Toggle de activación**: Habilitar/deshabilitar fácilmente
- **Autenticación Basic Auth**: Soporte para usuario/contraseña
- **Timeout configurable**: Control del tiempo límite (default: 30000ms)

#### Cuándo usar:
- Logging centralizado de todas las conversaciones
- Analytics global del workspace
- Integración con CRM para todas las interacciones
- Procesamiento uniforme de respuestas

#### Fases de Ejecución:

El Fertilizante Principal se ejecuta en **2 fases** durante el procesamiento de un mensaje:

**Fase 1 - Pre-procesamiento**:
- Se ejecuta **antes** de que el bot genere la respuesta
- Recibe el mensaje del usuario y contexto
- Puede modificar o enriquecer el contexto
- Útil para validaciones previas

**Fase 2 - Post-procesamiento**:
- Se ejecuta **después** de que el bot genera la respuesta
- Recibe la respuesta completa del bot
- Puede modificar la respuesta antes de enviarla al usuario
- Útil para logging y analytics

#### Estructura del Request:

```json
{
  "phase": "pre" | "post",
  "message": {
    "type": "text",
    "value": "Mensaje del usuario",
    "session_id": "abc-123"
  },
  "tree_id": "tree-uuid",
  "workspace_id": "workspace-uuid",
  "context": {
    "active_contexts": ["contexto1"],
    "parameters": {"param1": "valor1"}
  },
  "response": {
    // Solo en fase "post"
    "text": "Respuesta del bot",
    "branch_id": "branch-uuid",
    "confidence": 0.95
  }
}
```

#### Estructura del Response Esperado:

```json
{
  "success": true,
  "modified_response": "Respuesta modificada (opcional)",
  "additional_context": {
    "key": "value"
  },
  "metadata": {
    "processed_at": "2025-10-18T22:00:00Z"
  }
}
```

### 🔧 Fertilizantes Adicionales

Los **Fertilizantes Adicionales** son webhooks especializados para integraciones específicas que se ejecutan **bajo demanda** desde las Ramas.

#### Características:
- **Múltiples endpoints**: Crea tantos como necesites
- **Métodos HTTP flexibles**: GET, POST, PUT, PATCH, DELETE
- **Configuración individual**: Cada uno con su propia config
- **Testing independiente**: Prueba cada uno por separado
- **Headers personalizados**: Agrega headers HTTP específicos
- **Body templates**: Usa variables dinámicas en el body

#### Cuándo usar:
- Validación de datos específicos (email, teléfono, etc.)
- Consulta de información externa (stock, precios, disponibilidad)
- Acciones específicas (crear ticket, enviar email, etc.)
- Integraciones con APIs de terceros

#### Ejecución desde Ramas:

Los Fertilizantes Adicionales se ejecutan cuando una Rama los invoca explícitamente:

```json
{
  "branch": {
    "name": "consultar_stock",
    "webhook": {
      "fertilizer_id": "fertilizer-uuid",
      "execute_on": "match",
      "parameters": {
        "product_id": "{producto}",
        "quantity": "{cantidad}"
      }
    }
  }
}
```

#### Estructura del Request:

```json
{
  "fertilizer_id": "fertilizer-uuid",
  "branch_id": "branch-uuid",
  "parameters": {
    "producto": "laptop-123",
    "cantidad": "2"
  },
  "user_message": "Quiero 2 laptops",
  "session_id": "abc-123"
}
```

#### Estructura del Response Esperado:

```json
{
  "success": true,
  "data": {
    "stock_available": true,
    "quantity": 15,
    "price": 999.99
  },
  "message": "Hay 15 unidades disponibles"
}
```

## Configuración

### Acceder a la Configuración

1. En tu workspace, ve a **"Fertilizantes"** en el menú lateral
2. Verás dos secciones principales:
   - **Fertilizante Principal** (único por workspace)
   - **Fertilizantes Secundarios** (múltiples permitidos)

### Fertilizante Principal

**Configuración:**
- **URL**: Endpoint de tu webhook
- **Usuario/Contraseña**: Autenticación Basic Auth (opcional)
- **Timeout**: Tiempo límite en milisegundos
- **Toggle**: Activar/desactivar el fertilizante

**Pasos:**
1. Activa el toggle para habilitar
2. Completa la URL del webhook
3. Configura autenticación si es necesaria
4. Establece el timeout (por defecto 30000ms)
5. Guarda la configuración

### Fertilizantes Adicionales

**Configuración:**
- **Nombre**: Identificador del fertilizante
- **Descripción**: Propósito del webhook
- **URL**: Endpoint del webhook
- **Método HTTP**: GET, POST, PUT, PATCH, DELETE
- **Headers**: Headers HTTP personalizados (opcional)
- **Body Template**: Template del body con variables (opcional)
- **Timeout**: Tiempo límite en milisegundos

**Pasos:**
1. Haz clic en "Crear Fertilizante"
2. Completa nombre y descripción
3. Configura URL y método HTTP
4. Agrega headers si es necesario
5. Define body template con variables
6. Establece el timeout
7. Guarda la configuración
8. Usa el botón "Test" para probar individualmente

## Herramientas de Testing y Debugging

TreeFlow incluye herramientas avanzadas para facilitar el desarrollo y debugging de Fertilizantes:

### 🧪 Testing en Vivo

Cada Fertilizante Adicional tiene un botón "Test" que permite:

- **Simulación de datos**: Prueba con datos de ejemplo
- **Vista previa del request**: Ve exactamente qué se enviará
- **Ejecución desde el backend**: La prueba la hace el mismo ejecutor que usa la conversación (no el navegador), así que no choca con el CORS de tu API y no puede dar un resultado distinto al real. Una herramienta o un script sólo queda validado con estado **ok**
- **Respuesta en tiempo real**: Observa la respuesta del webhook
- **Validación de estructura**: Verifica que el formato sea correcto
- **Códigos de estado HTTP**: Identifica errores rápidamente

### 📊 Logs Detallados

El sistema registra automáticamente:

- **Timestamp preciso**: Cuándo se ejecutó el webhook
- **Request completo**: Headers, body, método
- **Response completo**: Status code, headers, body
- **Tiempo de respuesta**: Duración de la ejecución
- **Errores capturados**: Stack traces y mensajes de error

### 🚦 Estados de Ejecución

Cada ejecución de una herramienta o un script termina en uno de tres estados, con las mismas palabras y colores en el modo debug, en el detalle y en los editores:

| Estado | Significa | Qué hace el flujo |
|---|---|---|
| **✓ ok** (verde) | Respondió bien y trae sus variables de salida | Se aplican las salidas |
| **⚠ sin datos** (ámbar) | Respondió 2xx pero sin ninguna variable de salida (revisa los JSONPath) | Es una advertencia: el flujo sigue con la respuesta normal del nodo y las salidas toman su valor de respaldo, si lo tienen |
| **✗ error** (rojo) | No respondió, respondió 4xx/5xx, o dijo en el cuerpo que falló | Con valores de respaldo el flujo sigue; sin ellos, el usuario recibe el mensaje de error de la herramienta |

Un script no tiene código HTTP: sus estados son *ejecutado*, *sin datos* y *error*.

### 💬 Mensaje si Falla

El usuario final **nunca lee el error técnico**. Cada herramienta y script tiene un campo **Mensaje si falla**, con un chip por cada idioma del bot; si no lo rellenas, se usa un mensaje amable por defecto traducido (español, inglés, portugués, francés, alemán e italiano). El detalle técnico queda sólo en el modo debug de la consola.

### ✏️ Editar sin Salir del Flujo

Las tarjetas de herramientas y scripts del editor de nodos, y las fichas del modo debug de la consola, llevan un **lápiz** que abre el mismo editor de esta página, con sus pruebas y su guardado. Al guardar, el editor de nodos recarga la lista.

### 🔄 Retry Logic

Sistema de reintentos automáticos:

- **Backoff exponencial**: Espera progresivamente mayor entre reintentos
- **Máximo configurable**: Define cuántos reintentos permitir
- **Circuit breaker**: Protección contra servicios caídos
- **Notificaciones**: Alertas cuando fallan persistentemente

## Casos de Uso Comunes

### 📈 CRM Integration

**Fertilizante Principal** para enviar todos los leads:

```json
{
  "name": "CRM Sync",
  "url": "https://api.crm.com/leads",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer YOUR_TOKEN",
    "Content-Type": "application/json"
  },
  "body_template": {
    "lead": {
      "name": "{nombre}",
      "email": "{email}",
      "phone": "{telefono}",
      "source": "chatbot",
      "conversation_id": "{session_id}"
    }
  }
}
```

### ✅ Validación de Email

**Fertilizante Adicional** para validar emails:

```json
{
  "name": "Email Validator",
  "url": "https://api.emailvalidator.com/validate",
  "method": "GET",
  "parameters": {
    "email": "{email}"
  }
}
```

### 📦 Consulta de Stock

**Fertilizante Adicional** para verificar disponibilidad:

```json
{
  "name": "Stock Checker",
  "url": "https://api.inventory.com/stock/{product_id}",
  "method": "GET",
  "headers": {
    "X-API-Key": "YOUR_API_KEY"
  }
}
```

### 📧 Notificaciones por Email

**Fertilizante Adicional** para enviar emails:

```json
{
  "name": "Email Notifier",
  "url": "https://api.sendgrid.com/v3/mail/send",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer YOUR_SENDGRID_KEY",
    "Content-Type": "application/json"
  },
  "body_template": {
    "personalizations": [{
      "to": [{"email": "{email_destino}"}],
      "subject": "Nueva consulta desde chatbot"
    }],
    "from": {"email": "bot@tuempresa.com"},
    "content": [{
      "type": "text/plain",
      "value": "{mensaje}"
    }]
  }
}
```

## Mejores Prácticas

### ✅ Seguridad

- **Usa HTTPS**: Siempre endpoints seguros
- **Autenticación**: Implementa API keys o tokens
- **Validación**: Verifica datos antes de enviar
- **Rate limiting**: Protege tus APIs de sobrecarga

### ✅ Performance

- **Timeouts razonables**: No más de 30 segundos
- **Respuestas ligeras**: Solo datos necesarios
- **Caché cuando sea posible**: Reduce llamadas repetidas
- **Async cuando sea apropiado**: No bloquees la conversación

### ✅ Mantenibilidad

- **Nombres descriptivos**: Identifica fácilmente cada fertilizante
- **Documentación**: Describe el propósito de cada uno
- **Versionado**: Mantén versiones de tus APIs
- **Monitoreo**: Revisa logs regularmente

### ✅ Testing

- **Prueba en desarrollo**: Usa el botón Test antes de producción
- **Datos de ejemplo**: Ten casos de prueba preparados
- **Manejo de errores**: Verifica qué pasa cuando falla
- **Validación de respuestas**: Asegura que el formato sea correcto

## Troubleshooting

### Problema: Timeout constante

**Causas posibles:**
- API externa muy lenta
- Timeout configurado muy bajo
- Problemas de red

**Soluciones:**
- Aumenta el timeout
- Optimiza la API externa
- Implementa caché
- Considera hacer la llamada async

### Problema: Errores 401/403

**Causas posibles:**
- Credenciales incorrectas
- Token expirado
- Permisos insuficientes

**Soluciones:**
- Verifica usuario/contraseña
- Renueva el token
- Revisa permisos en la API externa

### Problema: Response inválido

**Causas posibles:**
- Formato JSON incorrecto
- Campos faltantes
- Tipos de datos incorrectos

**Soluciones:**
- Valida el JSON con un linter
- Revisa la documentación de la API
- Usa el testing en vivo para depurar

## Comparación: Principal vs Adicionales

| Característica | Fertilizante Principal | Fertilizantes Adicionales |
|----------------|------------------------|---------------------------|
| **Cantidad** | Único por workspace | Múltiples permitidos |
| **Ejecución** | Automática (todas las interacciones) | Bajo demanda (desde Ramas) |
| **Fases** | Pre y Post procesamiento | Una sola ejecución |
| **Uso principal** | Logging, analytics global | Integraciones específicas |
| **Configuración** | Toggle on/off | Individual por fertilizante |
| **Testing** | En producción | Botón Test individual |
