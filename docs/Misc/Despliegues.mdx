# Despliegue y Entornos

Esta guía explica cómo desplegar TreeFlow en diferentes entornos, gestionar configuraciones específicas y establecer un flujo de trabajo eficiente para el desarrollo, pruebas (staging) y producción.

## Arquitectura de Red de TreeFlow

Antes de abordar el despliegue, es clave entender cómo los diferentes puertos y servicios de TreeFlow conviven:
1. **Frontend**: Aplicación React compilada por Vite.
2. **Backend (Core API)**: API REST desarrollada con FastAPI en Python.
3. **Generative API**: Servicio independiente para las tareas de IA (aislamiento de recursos).
4. **Grafana/Prometheus**: Suite de observabilidad.
5. **Base de Datos**: PostgreSQL para almacenamiento robusto.

## Entorno de Desarrollo (Local)

El entorno de desarrollo ejecuta servicios en caliente con recarga automática para los desarrolladores.

1. Instala dependencias para Backend (Python VENV) y Frontend (NPM).
2. Se utilizan los puertos base por defecto (ej. 3000 para Frontend, 8000 para Backend).

## Entorno de Pruebas Dinámico (Staging Automático)

En marzo de 2026, introdujimos una arquitectura de Staging robusta y automatizada, solucionando históricas colisiones de puertos.

### 🌐 Redes Aisladas y CORS Dinámico
Al lanzar la versión de Staging vía Docker, **TreeFlow aisla sus puertos** (usa 3001 para Frontend y 8001 para Backend) en la red interna para evitar chocar con servicios locales de desarrollo u observabilidad. 

La aplicación maneja **CORS dinámico**. En lugar de tener URLs codificadas en duro (hardcoded) como `localhost`, toda la UI y el Backend resuelven su ubicación leyendo las variables desde un archivo `.env`, lo que permite que el Staging sea seguro y accesible desde el exterior.

### 🚇 Túneles con Cloudflared
El entorno de pruebas incluye automatización de túneles dinámicos a través de **Cloudflared**.
- Al arrancar Staging, Docker orquesta un contenedor de Cloudflare (`cloudflared`) usando `host networking`.
- El túnel expone de inmediato el Frontend y el Backend a una URL pública de internet HTTPS segura.
- Ideal para pruebas en vivo (Testear el Widget Web en tu celular, o mostrar avances al cliente).

## Pipeline de Despliegue (CI/CD)

TreeFlow cuenta con un flujo de **Integración y Despliegue Continuo (CI/CD)**.
- **Github Actions**: El repositorio ejecuta verificaciones y rutinas automáticas (`deploy workflow`) para asegurar la integridad de la rama principal.
- Utiliza la shell segura de Powershell (`pwsh`) para rutinas de automatización cruzada (Windows/Linux) durante el pase a producción.
