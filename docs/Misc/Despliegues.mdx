# Despliegue

TreeFlow corre en Docker. El código está en [github.com/Mizar-Contasti/treeflow](https://github.com/Mizar-Contasti/treeflow).

## En local

Desde la raíz del repositorio:

```bash
docker compose up --build
```

| Servicio | Dirección |
|---|---|
| La app | http://localhost:3000 |
| La API | http://localhost:8000 |
| Voz | http://localhost:8002 |
| PgAdmin | http://localhost:5050 |

La base es PostgreSQL 15. Se inicializa con `database/init/`, en orden alfabético, la primera vez que el volumen está vacío.

Para bajar los contenedores sin tocar los datos:

```bash
docker compose down
```

No borres volúmenes. Un `docker compose down -v`, un `docker volume rm` o un `docker system prune --volumes` destruye la base. No hay forma de recuperar esas conversaciones.

## En producción

El único despliegue es:

```bash
bash scripts/prod_complete.sh
```

Construye las imágenes con el servicio todavía en marcha y después las cambia. No se despliega con comandos sueltos de `docker compose`, ni con el script de PowerShell. El túnel público lo levanta ese mismo script, con Cloudflare (`cloudflared`): la app en `https://app.tree-flow.com` y la API en `https://api.tree-flow.com`.

La bajada permitida, sin `-v`, es:

```bash
docker compose -f docker-compose.prod.yml down --remove-orphans
```

## El widget fuera de tu máquina

Quien prueba el [widget](/docs/Canales/Web/setup) desde otro teléfono necesita una URL pública. En el despliegue de arriba la da el túnel. LocalTunnel no forma parte de TreeFlow: no hay un servicio que lo arranque ni una ruta que dependa de él.
