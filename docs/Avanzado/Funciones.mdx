# Funciones

Todo lo que el bot dice puede llevar una función dentro de `{ }`. Se rellena en el momento: los mensajes, las preguntas de un parámetro, las URL y los cuerpos de las herramientas, los bloques HTML.

Hay **una sola sintaxis**:

> Abres `{`, dentro pones una expresión, cierras `}`.
> Dentro, el **`$` distingue una variable de un texto**.

```
{$nombre}     el valor de la variable nombre
{nombre}      la palabra "nombre"
```

En Cafetería, el mensaje del pedido es una función. Si ya hay pedido, lo nombra. Si no, pregunta qué preparar.

![restaurante_hacer_pedido_response: la función con $pedido y el if](/img/funciones/mensaje.png)

```
{("¡Listo! Anoté " + $pedido + ". Te lo preparamos enseguida.") if $pedido else "¡Con gusto! ¿Qué te preparo?"}
```

| Llegó | Sale |
|---|---|
| `$pedido` = `2 empanadas de queso` | ¡Listo! Anoté 2 empanadas de queso. Te lo preparamos enseguida. |
| `$pedido` vacío | ¡Con gusto! ¿Qué te preparo? |

## Variables

`{$nombre}` imprime el valor. Los espacios dan igual.

```
{$nombre}                    Ana
{ $nombre }                  Ana
{$nombre.original_value}     ANA     · cómo lo escribió la persona
{$nombre.key_value}          ana     · el valor normalizado
```

Una variable que no existe se queda en blanco. No rompe el mensaje.

La pregunta de la cantidad, en `hacer_pedido`, mete lo que ya se capturó:

![Pregunta de numero: {$categoria_producto} y {$sabor_producto}](/img/funciones/pregunta.png)

```
¿Cuántas {$categoria_producto}s de {$sabor_producto} te preparo?
```

En la consola, con el flujo **Restaurante**, «quiero empanada de queso» no trae el sabor todavía. La pregunta de sabor usa la categoría que sí vino:

![La consola sustituye la categoría: ¿De qué sabor quieres empanada?](/img/funciones/consola.png)

Cuando después dice «queso», la pregunta de la cantidad ya sale armada: **¿Cuántas empanadas de queso te preparo?**

### El selector de variables

No hace falta acordarse de los nombres. Al teclear un `$` dentro de unas llaves, `{$`, sale una lista con las variables que puedes usar, y se va filtrando conforme escribes.

![El selector de variables: al escribir last_ sale la lista con las dos variables del sistema](/img/funciones/selector.png)

- **Flechas** para moverte, **Enter** o **Tab** para elegir, **Escape** para cerrar la lista.
- También puedes hacer clic en una.
- Al elegir una variable suelta, la llave se cierra sola: `{$no` → `{$nombre}`. Dentro de una expresión (`{$edad > 18 ? $no`) no se cierra, porque lo que sigue lo escribes tú.
- No distingue mayúsculas ni acentos.
- Detrás de un punto (`{$api.`) no sugiere: ahí ya estás leyendo dentro del valor.

La lista trae los **parámetros de las intenciones** del bot que tienes seleccionado, con la intención de la que salen, y las dos variables del sistema, marcadas como *Sistema*. Sale en los textos de las respuestas, tanto en el mensaje de texto como en los párrafos de los elementos enriquecidos.

## Variables del sistema

El motor deja dos listas en cualquier bot. No se crean en Entidades ni en un parámetro, no se configuran y no se apagan. Al teclear `{$` salen en el selector, marcadas como *Sistema*, junto a los parámetros de las intenciones.

| Variable | Qué contiene |
|---|---|
| `{$last_utterance}` | Lo último que escribió la persona |
| `{$last_no_match}` | La última frase que el bot no entendió |

Las dos viven en la sesión: las leen la respuesta, las herramientas y los scripts de este turno, los nodos que vengan después, y el turno siguiente. Si el bot ya tenía un parámetro con uno de esos nombres, el motor lo sustituye.

### `{$last_utterance}`

Se guarda al llegar el mensaje, antes de detectar la intención. En ese mismo turno ya vale lo que acaba de escribir.

```
Dijiste "{$last_utterance}".
```

Si escribió `quiero una pizza voladora`, sale **Dijiste "quiero una pizza voladora".**

Cambia en cada mensaje que trae texto. El anterior no se conserva. Un turno sin texto (`sys.no-input`) no la toca.

### `{$last_no_match}`

Se guarda cuando el turno queda en `sys.no-match`, antes de contestar y antes de correr las herramientas y scripts de ese nodo. Sirve para repetirle la frase:

```
No entendí "{$last_no_match}", ¿puedes decirlo de otra forma?
```

Si esa frase fue `quiero una pizza voladora`, sale **No entendí "quiero una pizza voladora", ¿puedes decirlo de otra forma?**

Un turno que sí se entiende no la cambia: sigue valiendo la última frase fallida. Mientras no haya habido ningún no-match, la variable no existe y el hueco sale en blanco.

## Textos

Una palabra sin `$` es texto. Las comillas simples y las invertidas se tratan como dobles.

```
{"hola"}     hola
{'hola'}     hola
{`hola`}     hola
{hola}       hola
```

Eso importa al comparar:

```
{$color == rojo}       compara con el texto "rojo"
{$color == $otro}      compara con otra variable
```

`{$sabor == queso}` es verdadero si el sabor capturado es queso. `{$sabor == $otro}` compara dos variables.

## Condiciones

```
{$edad > 18 ? "adulto" : "menor"}            adulto
{if $edad > 18 ? "adulto" : "menor"}         adulto   · el "if" delante es opcional
{$edad > 18 ? "adulto"}                      adulto   · sin la otra rama, si no se cumple no sale nada
```

El pedido de arriba es el mismo mecanismo: `if $pedido` elige el texto de confirmación; si no hay pedido, elige la pregunta.

Se pueden anidar con paréntesis:

```
{ $a > 1 ? ($b > 1 ? "los dos" : "sólo a") : "ninguno" }
```

Y componer con texto alrededor:

```
{ "Tienes " + $n + " mensajes" }
{ $nombre + ", el mayor es " + ($a if $a > $b else $b) }
```

La reserva hace lo mismo con el contacto. Si vino, lo nombra. Si no, la confirmación no lo menciona:

```
{("Te confirmamos a " + $contacto + ".") if $contacto else ""}
```

## Cálculos

Dos números se suman. Un número junto a un texto se pega.

```
{$precio * 120}          18000      · si precio es 150
{$a + $b}                10         · si a es 6 y b es 4
{"Total: " + $a}         Total: 3   · con texto, se concatena
{$b - $a}                4
{round($precio, 2)}      150.4
```

Un precio de menú cabe en la respuesta así:

```
{ "Son $" + ($precio * $numero) + " por " + $numero + " " + $categoria_producto }
```

Con precio `45` y número `2` sale **Son $90 por 2 empanada**.

## Funciones y métodos

| Escribes | Qué hace | Ejemplo |
|---|---|---|
| `{len($nombre)}` | cuántos **caracteres** tiene | `Ana` → `3` |
| `{count($producto)}` | cuántas **veces** lo dijo en la frase | dos productos → `2` |
| `{round($x)}` `{round($x, 2)}` | redondear | `150.36` → `150.36` o `150` |
| `{min($a,$b)}` `{max($a,$b)}` `{abs($x)}` `{sum($lista)}` | los de siempre | |
| `{str($x)}` `{int($x)}` `{float($x)}` `{bool($x)}` | convertir | |
| `{$nombre.upper()}` | mayúsculas | `ana` → `ANA` |
| `{$nombre.capitalize()}` | primera en mayúscula | `ana` → `Ana` |
| `{$texto.strip()}` | quita espacios de las orillas | |

`len()` y `count()` no miden lo mismo. `len($nombre)` con Ana da **3**. `count($producto)` da **2** si en la misma frase nombró dos productos.

## Cuando la persona repite algo

Si en una frase caben varios valores del mismo parámetro, se indexan:

```
{$producto[0]}        el primero
{$producto[1]}        el segundo
{count($producto)}    cuántos vinieron
{$producto}           el primero, como siempre
```

«quiero una empanada y un café» puede dejar dos productos. `{$producto[0]}` es el primero y `{$producto[1]}` el segundo. `{$producto[0]}` también funciona cuando sólo vino uno: un parámetro simple se comporta como una lista de uno.

`{$pedido}` de una compuesta no imprime la estructura. Imprime el resumen legible, por ejemplo **2 empanadas de queso**.

## Respuestas de herramientas

Una herramienta puede guardar su respuesta entera en un parámetro. Se baja dentro con puntos e índices:

```
{$api}                 el objeto entero, como JSON
{$api.estado}          un campo
{$api.items[0]}        el primer elemento de una lista
{$api.items}           la lista
```

Si la herramienta dejó `{"estado": "listo", "items": ["empanada", "café"]}` en `$api`:

| Escribes | Sale |
|---|---|
| `{$api.estado}` | listo |
| `{$api.items[0]}` | empanada |
| `{$api}` | `{"estado": "listo", "items": ["empanada", "café"]}` |

## Lo que el motor no toca

Sólo se evalúa lo que parece código. Esto atraviesa intacto:

```
<style>.tarjeta { color: red; padding: 4px }</style>     el CSS de un bloque HTML
{"cliente": "Ana", "cantidad": 2}                        un cuerpo JSON
^\d{4}-\d{2}-\d{2}$                                      una regex
```

Un hueco **dentro** de un JSON sí se resuelve. Es el cuerpo de una herramienta:

```
{"cliente": "{$nombre}", "id": {$id}}
```

sale como `{"cliente": "Ana", "id": 42}`. En un HTML, `<b>{$nombre}</b>` sale `<b>Ana</b>` y el CSS de al lado no se toca.

## Limitaciones

- No se pueden poner llaves literales dentro de una cadena de una expresión. En `{ "el formato es {a}" }`, ese `{a}` es un hueco como cualquier otro.
- `{5}` no se evalúa. Un número suelto se deja tal cual, porque `\d{3}` en una regex es un cuantificador. Los números sí cuentan dentro de una expresión: `{$a > 5}`.

Los parámetros se usan desde las [respuestas](/docs/Avanzado/Parametros#en-respuestas) y desde las [capturas](/docs/Fundamentos/Capturas).
