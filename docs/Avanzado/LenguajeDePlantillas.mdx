# Lenguaje de plantillas

Todo lo que el bot dice puede llevar huecos que se rellenan en el momento: los
mensajes, las preguntas del slot filling, las URL y los cuerpos de las
herramientas, los bloques HTML.

Hay **una sola sintaxis**:

> Abres `{`, dentro pones una expresión, cierras `}`.
> Dentro, el **`$` distingue una variable de un texto**.

```
{$nombre}     el valor de la variable nombre
{nombre}      la palabra "nombre"
```

![El texto de un mensaje: ahí se escriben los huecos](/img/mensajes/editor.png)

Esa es toda la regla. Lo demás son consecuencias.

## Variables

```
{$nombre}                    Ana
{ $nombre }                  Ana          · los espacios dan igual
${nombre}                    Ana          · la forma antigua también vale
{$nombre.original_value}     ANA          · cómo lo escribió el usuario
{$nombre.key_value}          ana          · el valor normalizado
```

Una variable que no existe se queda en blanco. No rompe el mensaje.

## Textos

Una palabra sin `$` es texto. Las comillas simples y las invertidas se tratan
como dobles.

```
{"hola"}     hola
{'hola'}     hola
{`hola`}     hola
{hola}       hola
```

Esto importa al comparar:

```
{$color == rojo}       compara con el texto "rojo"
{$color == $otro}      compara con otra variable
```

## Condiciones

```
{$edad > 18 ? "adulto" : "menor"}            adulto
{if $edad > 18 ? "adulto" : "menor"}         adulto   · el "if" delante es opcional
{$edad > 18 ? "adulto"}                      adulto   · el ":" también es opcional
```

Si no se cumple y no pusiste la otra rama, no sale nada. El hueco desaparece.

Se pueden anidar con paréntesis:

```
{ $a > 1 ? ($b > 1 ? "los dos" : "sólo a") : "ninguno" }
```

Y componer con texto alrededor:

```
{ "Tienes " + $n + " mensajes" }
{ $nombre + ", el mayor es " + ($a if $a > $b else $b) }
```

## Cálculos

```
{$precio * 120}          18000
{$a + $b}                10        · dos números se suman
{"Total: " + $a}         Total: 3  · con texto, se concatena
{$b - $a}                4
{round($precio, 2)}      150.4
```

## Funciones y métodos

| Escribes | Qué hace |
|---|---|
| `{len($nombre)}` | cuántos **caracteres** tiene |
| `{count($producto)}` | cuántas **veces** lo dijo el usuario en la frase |
| `{round($x)}` `{round($x, 2)}` | redondear |
| `{min($a,$b)}` `{max($a,$b)}` `{abs($x)}` `{sum($lista)}` | los de siempre |
| `{str($x)}` `{int($x)}` `{float($x)}` `{bool($x)}` | convertir |
| `{$nombre.upper()}` `{$nombre.capitalize()}` `{$texto.strip()}` | métodos de texto |

`len()` y `count()` son cosas distintas. `len($nombre)` con "Ana" dentro da
**3**. `count($producto)` da **2** si el usuario nombró dos productos en la
misma frase.

## Cuando el usuario repite algo

Si en una frase caben varios valores del mismo parámetro, se indexan:

```
{$producto[0]}        el primero
{$producto[1]}        el segundo
{count($producto)}    cuántos vinieron
{$producto}           el primero, como siempre
```

`{$producto[0]}` funciona aunque sólo haya venido uno: un parámetro simple se
comporta como una lista de uno.

## Respuestas de herramientas

Una herramienta puede guardar su respuesta entera en un parámetro. Se baja
dentro con puntos e índices:

```
{$api}                 el objeto entero, como JSON
{$api.estado}          un campo
{$api.items[0]}        el primer elemento de una lista
{$api.items}           la lista
```

## Lo que el motor no toca

Sólo se evalúa lo que parece código. Esto atraviesa la interpolación intacto:

```
<style>.tarjeta { color: red; padding: 4px }</style>     el CSS de un bloque HTML
{"cliente": "Ana", "cantidad": 2}                        un cuerpo JSON
^\d{4}-\d{2}-\d{2}$                                      una regex de validación
```

Un hueco **dentro** de un JSON sí se resuelve. Es lo que hace falta para el
cuerpo de una herramienta:

```
{"cliente": "{$nombre}", "id": {$id}}
```

sale como `{"cliente": "Ana", "id": 42}`.

## Limitaciones

- No se pueden poner llaves literales dentro de una cadena de una expresión.
  En `{ "el formato es {a}" }`, ese `{a}` es un hueco como cualquier otro.
- `{5}` no se evalúa. Un número suelto se deja tal cual, porque `\d{3}` en
  una regex es un cuantificador. Los números sí cuentan dentro de una
  expresión: `{$a > 5}`.

## Si vienes de la sintaxis antigua

Antes existían `{{ ... }}` y `{ ... }`. **`{{ ... }}` ya no existe.** Un texto
sin migrar no da error: imprime otra cosa.

```
{{$nombre}}   ->  {Ana}    la llave de fuera se queda suelta
```

| Antes | Ahora |
|---|---|
| `{{nombre}}` | `{$nombre}` — hay que añadir el `$` |
| `{{$nombre}}` | `{$nombre}` |
| `{{ $a > 1 ? "x" : "y" }}` | `{ $a > 1 ? "x" : "y" }` |
| `{{len($producto)}}` | `{count($producto)}` — cambió de significado |

Sin el `$`, `{nombre}` imprime la palabra "nombre". Y `len()` ahora mide
caracteres, no cuántas veces vino el parámetro.

Los parámetros se usan desde las [respuestas](/docs/Avanzado/Parametros#en-respuestas)
y desde las [capturas](/docs/Fundamentos/Capturas).
